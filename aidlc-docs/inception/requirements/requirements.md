## 1. Project Overview

### 1.1 Concept

「走った風になる」— スタート地点とゴール地点を指定すると、Google Street Viewの画像を使ってブラウザ上で「自分が走っている風」の体験を生成するWebアプリケーション。

「人をダメにするアプリ」として、実際には一歩も動かずに「今日も走った」という達成感と罪悪感の解消を提供する。

### 1.2 体験シナリオ

#### シナリオ1: 平日夜の罪悪感解消

> 金曜の夜22時。今週も一度もジムに行けなかった。SNSには友人のランニング記録が流れてくる。「自分もやらなきゃ」——でも、もう動く気力はない。
>
> アプリを開く。「今日は代々木公園を一周しよう」。スタートをタップすると、画面に夜の代々木公園周辺の街並みが流れ始める。距離カウンターが刻々と増えていく。2.3km...2.4km...。
>
> 10分後、「5km完走！ 推定消費カロリー: 320kcal」の表示。ソファから一歩も動いていないのに、なぜか「今週もちゃんと走った」という気持ちになっている。罪悪感が消えた。明日もまた走ろう（走らないけど）。

#### シナリオ2: 朝の通勤ルート

> 月曜の朝。通勤電車に揺られながら、ふとアプリを開く。「自宅→最寄り駅」のコースを選択。画面には見慣れた通勤路の景色が流れる。「今朝は駅まで走った」——実際には電車の中だけど。到着通知:「1.2km完走！ 素晴らしいスタートです！」。なんだか今日一日、少しだけ健康的な気分で過ごせそうだ。

### 1.3 人をダメにするメカニズム

#### サイクル構造

```
[1. トリガー] 「走らなきゃ」という罪悪感
      |
      v
[2. 代替行動] アプリで「走った風」体験
      |
      v
[3. 偽りの報酬] 数値による達成感の錯覚
      |
      v
[4. 罪悪感の消失] 「今日は走ったからOK」
      |
      v
[5. 行動の先送り] 実際のランニングをしない正当化
      |
      v
[1. トリガー再発] 翌日また罪悪感が生まれる → サイクル繰り返し
```

#### メカニズム詳細

| # | メカニズム | 心理的原理 | アプリでの実装 |
|---|---|---|---|
| 1 | **トリガー（罪悪感）** | 認知的不協和：「健康でありたい自分」と「運動しない自分」のギャップ | アプリを開くきっかけ自体がユーザーの内発的動機 |
| 2 | **代替行動（努力の置換）** | 代償行動：本来の行動の代わりに、より楽な行動で心理的欲求を満たす | Street View画像の連続表示による「走っている感覚」の提供 |
| 3 | **偽りの報酬（数値の錯覚）** | 数値フィードバック効果：具体的な数字が「やった感」を脳に与える | 距離・カロリー・時間のリアルタイム更新 |
| 4 | **罪悪感の消失（自己欺瞞）** | 自己正当化バイアス：「やった」という事実（虚構でも）があれば自分を許せる | 完走メッセージ、記録としての残存 |
| 5 | **行動の先送り（習慣の固定化）** | 即時満足バイアス：楽に得られる満足を選び続ける | 毎回数分で「完走」できる手軽さ |

#### なぜ離れられないのか

- **コストが極めて低い**: ソファから動かず、数分で完了する
- **報酬が即座に得られる**: 完走した瞬間に達成感が発生する
- **社会的に無害に見える**: 「ランニングアプリを使っている」と言えば健康的に聞こえる
- **罪悪感のループ**: 解消しても翌日また生まれるため、毎日使う理由がある

### 1.4 アプリのトーン/世界観

#### アプリの人格

| 属性 | 方向性 | 具体例 |
|---|---|---|
| **立ち位置** | ユーザーの「共犯者」 | 一緒にサボることを楽しむ相棒。説教しない、否定しない |
| **ユーモア** | 自虐的・シニカル | ユーザーが「ダメだな自分」と笑える。深刻にならない |
| **称賛スタイル** | 過剰で大げさ | 実際には何もしていないのに全力で褒める。そのギャップが面白い |
| **罪悪感への態度** | 全肯定・甘やかし | 「走った（風）だからOK！」と背中を押す |

#### UIメッセージ例

**走行中**:
- 「いい調子です！（ソファの上で）」
- 「風を感じますか？（エアコンの風かもしれませんが）」

**完走時**:
- 「お疲れさまでした！ 今日も立派に走りました（走ってない）」
- 「消費カロリー: 320kcal（理論値）」
- 「あなたの脚は今日も休まりました。明日も休めましょう。」

**起動時**:
- 「おかえりなさい。今日もどこかへ走りに行きますか？（行きませんが）」
- 「昨日は渋谷まで走りましたね。今日はどこへ？」

#### ユーザーとの関係性

- **従来のフィットネスアプリ**: アプリ = コーチ（叱咤激励する存在）
  - 「今日はサボりましたね。明日は頑張りましょう」
- **このアプリ**: アプリ = 共犯者（一緒にサボる存在）
  - 「今日も走った（風）！最高！明日もサボろう！」

#### アンチパターン（やってはいけないこと）

- ❌ ユーザーを責める・説教する（「実際に走った方がいいですよ」）
- ❌ 真面目すぎるトーン（「健康のために本当のランニングも検討してください」）
- ❌ 罪悪感を煽る（「今日はまだ走っていません」的な通知）
- ❌ 他のフィットネスアプリと同じ真剣さで語る

### 1.5 Target Users

- **Primary**: 運動不足を自覚しているが実際に走る気力がない20〜30代の社会人
- **Secondary**: ダイエットに興味はあるが継続できない全年齢層
- **Potential Future**: 旅行好きだが実際に行けない人（バーチャル旅行としての利用）

## 2. Functional Requirements

### 2.1 MVP Core Features (Phase 1)

#### FR-001: コース指定
- ユーザーがスタート地点とゴール地点を地図上で指定できる
- 2地点間のルートを自動計算する
- ルートに沿ったStreet View画像の取得ポイントを決定する

#### FR-002: バーチャルランニング体験（リアルタイム表示）
- ブラウザ上でStreet View画像を連続表示し、走っている風の体験を生成する
- JavaScript/Canvasを使用したクライアントサイドレンダリング
- 適切な速度感（ランニングペース）で画像を切り替える
- 視点の移動がスムーズに見えるよう画像間のトランジション処理
- ルート上の現在位置をミニマップまたはメイン地図上にリアルタイム表示する

#### FR-003: 罪悪感解消の演出
- 走行距離カウンター表示（「今日は5km走りました！」）
- 推定消費カロリー表示（「320kcal消費！」）
- 走行時間の表示（「25分間ランニング完了！」）

### 2.2 Future Features (Post-MVP)

| Priority | Feature | Description |
|---|---|---|
| Phase 2 | 手振りアニメーション | 走っている臨場感を出すための手振りオーバーレイ |
| Phase 2 | 動画ファイル出力 | mp4としてダウンロード・共有可能にする（サーバーサイド生成） |
| Phase 2 | マップ上のコース表示 | 走った（風の）コースをマップ上に可視化 |
| Phase 3 | ユーザーアカウント | ソーシャルログイン、走行記録の保存 |
| Phase 3 | アバター＆体型変化 | 身長・体重を入力してアバターを作成。走った風の動画を完了するたびにアバターが少しずつ痩せていくアニメーション。累積走行距離に応じた体型変化の可視化 |
| Phase 3 | 習慣化の仕掛け | ストリーク、連続記録、通知リマインダー |
| Phase 3 | ゲーミフィケーション | レベルアップ、バッジ、チャレンジ |
| Phase 3 | ご褒美ラーメン提案 | 消費カロリーに見合った付近のラーメン店をおすすめ。さらにそのラーメン店までの「走った風」動画コースを自動提案する。走った（風）カロリーを即帳消しにする共犯者ムーブ |
| Phase 3 | ソーシャル機能 | コース共有、友人との体験共有 |
| Phase 4 | コレクション機能 | ご近所制覇、世界一周チャレンジ |
| Phase 4 | テイスト変更 | 異世界風、箱根駅伝風などの動画テイスト |
| Future | AR/VR対応 | 没入型体験 |
| Future | 推しの聖地コース | アニメ・映画ロケ地の自動コース生成 |

## 3. Non-Functional Requirements

### 3.1 Platform
- **MVP**: Webアプリケーション（ブラウザベース）
- **Future**: モバイル対応（レスポンシブ or PWA or ネイティブアプリ）

### 3.2 Performance
- Street View画像の取得・表示がスムーズであること（体感的にカクつかない）
- 初回ロード時間: 3秒以内（コア体験開始まで）

### 3.3 Scalability
- MVP: 小規模（個人利用〜数十人程度）
- 将来的な拡張を考慮した設計は不要（MVPフェーズ）

### 3.4 Security
- MVP: セキュリティ拡張ルールはスキップ（プロトタイプレベル）
- Google Maps APIキーの適切な管理（環境変数、リファラー制限）

### 3.5 Authentication
- MVP: アカウント不要（認証なし）
- 将来的にソーシャルログインを追加予定

## 4. Technical Context

### 4.1 API Dependencies
- **Google Maps Platform**:
  - Street View Static API（画像取得）
  - Directions API（ルート計算）
  - Maps JavaScript API（地図表示・地点指定UI）

### 4.2 Architecture (MVP)
- **クライアントサイド中心**:
  - ブラウザ上でCanvas/JavaScriptによるリアルタイム画像表示
  - 動画ファイル生成なし（リアルタイム表示のみ）
- **サーバーサイド（最小限）**:
  - Google Maps APIキーのプロキシ（キーをクライアントに露出させない）
  - 将来的に動画ファイル生成機能を追加する際のバックエンド基盤

### 4.3 Development Team
- 小規模チーム（2〜3名）

## 5. Competitive Positioning

### 5.1 Competitive Landscape

| Category | Competitors | Key Difference |
|---|---|---|
| バーチャルフィットネス | Zwift, Peloton | 実際に運動する前提 → 本アプリは運動不要 |
| バーチャル散歩/旅行 | Google Earth, GeoGuessr, Randonautica | 「走る」体験としての演出がない |
| ランニング記録 | Nike Run Club, Strava | 実際に走る前提 → 本アプリは走らない |
| ストリートビュー動画 | Google Earth Studio, Mapillary | ランニング体験としての演出・罪悪感解消がない |

### 5.2 Differentiation
- **根本的差別化**: 「実際に走らなくていい」
- **コンセプト差別化**: 「人をダメにする」エンタメ/自虐的な切り口
- **体験差別化**: 罪悪感解消の演出（距離・カロリー・時間表示）

## 7. Constraints & Assumptions

### 7.1 Constraints
- Google Maps Platform APIの利用料金（無料枠あり、超過時は従量課金）
- Street View画像のカバレッジ（すべての道路にStreet Viewがあるわけではない）
- APIレート制限への対応

### 7.2 Assumptions
- ユーザーはモダンブラウザ（Chrome, Firefox, Safari, Edge最新版）を使用
- インターネット接続が安定している環境での利用を想定
- Google Maps PlatformのAPIキーを取得済み（開発者が設定）

### 7.3 Out of Scope (MVP)
- 手振りアニメーション合成
- 動画ファイル（mp4）出力
- ユーザーアカウント・認証
- ソーシャル機能
- AR/VR対応
- モバイルネイティブアプリ
